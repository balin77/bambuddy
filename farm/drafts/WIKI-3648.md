### 1b. New section "Paused Prints"

Insert as a new `###` section **after** `### What Each Entry Means` (and before the sections that follow it):

````markdown
### Paused Prints

A print that has paused is the most urgent thing on a farm, so its entry sits at the **top of the printer's group**, above every other entry, and a paused printer with no waiting job gets a group of its own at the top of the list ([#3648](https://github.com/maziggy/bambuddy/issues/3648)). It counts in the number on the **To do** badge.

The first line names the file, how far it got and what is left, for example **Benchy · 42% · 1 h 5 min left**. Parts the printer did not report are left out. The second line says why the print paused:

| Reason | Text |
|--------|------|
| Filament ran out in an AMS | **Filament ran out in A2. Load PLA Lava Red into A3, then resume.** When the printer names only one of the two slots the text names that one; when it names none: **Filament ran out. Check the printer screen for the slot it expects.** |
| Filament ran out on the external spool | **Filament ran out on the external spool. Load a new spool, then resume.** |
| An error or warning | The printer's own text, for example **The door is open**, followed by **(+2 more)** when other faults are active. A fault without text shows its code (**Error 0500-0300-0002-000E**) |
| No reason reported | No second line |

A runout is named before any other fault. Slots are named as on the printer card (**A2**, **HT-A**, **Ext**) and the filament is named by its type and colour name as on the card. When the slot that ran out is empty now, the filament shown is the one the expected slot reports, or **matching filament** when neither is known.

!!! note "Who sees what"
    Only printers you may see are listed. The **file name** is shown only with the `printers:read` permission; without it the entry shows progress and time left. A user who may only read their own queue items still sees a paused printer in their printer scope, with the waiting jobs they may see under it.

!!! info "How it stays steady"
    The printer rebuilds its fault list with every status message, so a reason can vanish for a moment. The reason of a pause is kept for up to 20 seconds after it was last reported, and forgotten as soon as the printer is no longer paused. The list updates when a printer pauses, resumes or its faults change, without waiting for the next refresh.

There is no **Resume** button in the list: it tells you what to do, and the printer card resumes the print.
````

          "kind": "print_paused",

### 2b. Field table

In the field table of `### Get To Do List`, add `print_paused` to the list of values of `entries[].kind` and these rows after the `entries[].printers` row:

```markdown
| `entries[].kind` = `print_paused` | A print on the printer is paused and waits for a person. First entry of its group; counted. `jobs` lists the waiting jobs of that printer, if any |
| `entries[].paused` | `print_paused` only, else absent or `null` |
| `entries[].paused.job_name` | The paused file. `null` when the caller has no `printers:read` permission |
| `entries[].paused.progress`, `remaining_minutes` | Percent done and minutes left; `null` when the printer did not report them |
| `entries[].paused.cause` | `runout_ams` (an AMS slot ran out), `runout_external` (the external spool ran out), `error` (the most severe active fault) or `paused` (no reason reported) |
| `entries[].paused.ran_out`, `expected` | `runout_ams` only: the slot that ran out and the slot the printer now expects. Each has `ams_id`, `tray_id`, `is_ht`, `is_external`, `ams_type` and, from the live tray, `type`, `color`, `tray_info_idx`, `tray_sub_brands` (empty for an empty slot). `null` when the printer does not say |
| `entries[].paused.error` | `error` only: `{code, description}`; `code` as the printer screen writes it, `description` may be `null` |
| `entries[].paused.more_errors` | The number of other active faults besides the one named |
```

Then add after the table:

````markdown
Only printers in the caller's printer scope are listed. The fields are additive: clients that ignore them see the same response as before, apart from the new entry kind.
````
