## Description

When a queued job is held because a loaded spool has too little filament left (the queue's filament check, #1496), the **Queue Job Waiting** notification carried the internal code `filament_short` as its reason:

```
Queue Job Waiting
KnittedPenguin.9x.A1.swap.jobox waiting for A1
filament_short
```

The other waiting reasons are sentences. The scheduler already has the facts at hand (which slot, which material, how many grams are left and how many the job needs), they just were not used in the text. This PR words them:

```
Not enough filament on Workshop A1: PLA in A2 (12 g left, needs 40 g)
```

- One entry per short spool, joined with commas.
- The slot is named the way the other alerts name it (`A2`, `HT-A`, `Ext-L`, and per-hotend `Ext-n`), through the existing `_ams_slot_label`, so the notification and the Inventory page call a tray the same thing.
- The printer's name is in the sentence ("on Workshop A1"). Before, the notification only had the printer **model**.
- A spool whose weight is unknown shows only what the job needs: "PLA in A2 (needs 40 g)".
- A short spool without a known material is called "Filament" instead of leaving a gap ("Filament in A2 (12 g left, needs 40 g)").
- The queue row itself and the scheduler's decisions are unchanged: only the text handed to the notification changes. No migration, no new setting, no new dependency.

## Changes Made

- `backend/app/services/print_scheduler.py`: `_describe_deficit_for_notification` builds the sentence from the `FilamentDeficit` list (material, slot, grams) and the printer's name; `_block_on_filament_deficit` passes it as the `waiting_reason` instead of `"filament_short"`, with the printer's tray layout for the slot names. A deficit with no slot shows just the material; one with no material is called "Filament".
- `backend/tests/unit/test_scheduler_filament_deficit.py`: tests for the sentence (below).
- `backend/tests/integration/test_notification_scope_without_printer.py`, `backend/tests/unit/test_scheduler_loaded_filament_first_3587.py`: the two assertions that expected the code now expect the sentence.
