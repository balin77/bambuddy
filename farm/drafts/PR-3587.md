## Description

Today a queued job whose filament is not on its printer is held ("Needs PLA Earth Brown", force colour match, filament deficit) and, for a job pinned to a printer, the job stays in front of that printer while jobs behind it that would fit have to wait. This PR adds an optional queue mode, **Loaded filament first**, that runs the jobs whose filament is loaded first, with a **maximum wait** so no job is starved.

**Behaviour (mode on)**

- **Skip instead of stage.** A job whose filament does not fit (unmatched slot #2799, **Force color match** #3280, filament deficit #1496) is skipped. It stays pending, is not staged for a manual start, and its printer stays free for later jobs. It starts by itself once the filament fits. The row reads **Waiting for filament: … · priority in N h**.
- **Maximum wait.** After `queue_max_wait_hours` (counted from the time the job was queued or its scheduled start, whichever is later) the job gets priority (**· has priority**). Its printer is then kept free for it, so jobs behind it no longer take that printer. For a job for a printer model, the printer kept free is the first idle printer in the configured model dispatch order (#3480, #2915); later queue items read **Busy: X (kept free for a job waiting for filament)**.
- **Notification.** The existing **Job Waiting** notification is sent once: when the job gets priority, or, with no limit, when it starts waiting. Not on every scheduler pass.
- **Smart plugs.** A pinned job whose printer is off behind an auto-on smart plug does not switch the printer on while the printer's last-known trays show the shortfall. With no tray reading the printer is woken as before.
- **Unchanged.** **Print Anyway**, staged jobs, plate gates, `require_previous_success`, the #2771 failure, Shortest Job First and queue positions work as before. Positions are never rewritten.
- **Mode off (default) = identical to today.**

**Settings** (Settings → Workflow → Queue & Dispatch, card **Loaded Filament First**)

|-----|---------|-------|

## Changes Made

**Settings (schemas, API, backup restore)**
- `AppSettings`: `queue_loaded_filament_first` (bool, default false) and `queue_max_wait_hours` (`int | None`, default 48, 1..8760; null = no limit). `AppSettingsUpdate` has the same range. The bounds are constants shared by the schema, the read-back and the scheduler.
- `settings.py`: the bool joins `_BOOL_SETTING_KEYS`. `queue_max_wait_hours` has its own read-back branch like `default_printer_id`: the stored literal `None` reads as null, and a value outside the range falls back to the default (logged).
- `github_restore.py`: `queue_max_wait_hours` is added to `_READS_A_SAVED_NULL`, so a Git backup restore keeps "no limit" instead of refusing the null.

**Scheduler (`print_scheduler.py`)**
- Both settings are read once per `check_queue` pass.
- Pinned jobs: with the mode on, the deficit/unmatched findings skip the job (`hold_item(..., notify=False)`) instead of staging it. Without priority the printer is not marked busy. With priority the printer is reserved (`mark_busy`) and later items read "Busy: X (kept free for a job waiting for filament)". The finders are read-only helpers split out of `_block_on_filament_deficit` / `_block_on_unmatched_filament`, which keep their exact behaviour for mode off.
- Model jobs: `_find_idle_printer_for_model(..., short_is_missing=True)` passes over a short printer instead of using it as a fallback. The matcher's reason gets the priority suffix. With priority, `_reservable_printer_for_model` reserves the first idle, connected printer with a fitting nozzle, walking candidates in their order and each model's printers in the configured dispatch order. It is recomputed every pass, never stored, and does not set `item.printer_id`, so keep-warm, preheat pin and drying bookkeeping are untouched. Keep-warm leaves reserved printers out.
- The post-assignment deficit/unmatched gates (race fallbacks) release the assignment and skip the job in the same way.
- A pinned job behind an auto-on plug is not woken while its last-known trays show the shortfall (`_wake_declined_for_filament`; no inventory or Spoolman lookup while the printer is off).
- `_notify_filament_wait_once` sends the **Job Waiting** notification once per state. The state is kept in memory and in the saved reason, so a "Busy" reason in between or a restart does not repeat it.

**Frontend**
- `SettingsPage.tsx`: card **Loaded Filament First** with the toggle and a **Maximum wait (hours)** field. The field is disabled while the mode is off. Empty saves null. An invalid value stays a draft with an inline message, so it cannot cause a 422 that blocks later saves. Both keys are in `hasChanges` and the save payload (null-safe, never `?? 48`). New settings search entry.
- `waitingReason.ts` `formatWaitingReason()`: translates the "Waiting for filament: " and "No matching material/color. Waiting on" prefixes in every such reason (also behind a model label in cross-model reasons) and the "priority in N h" / "has priority" suffix. Everything else stays as the backend wrote it. `QueuePage.tsx` renders the row with it.
- `QueuePage.tsx`: a job skipped for filament no longer blocks the ETA of the job behind it; one with priority still does.
- New i18n keys in all 16 locales, with real translations. `client.ts` types.

## Additional Notes

**Design decisions**
- **Greedy skip.** The queue is walked in its normal order. A job that cannot run because of filament is passed over and the next job that fits takes the printer. Queue positions and SJF order are never rewritten.
- **Reservation choice.** Only a job past its maximum wait reserves a printer. For a pinned job that is its own printer. For a model job it is the first idle printer in the configured dispatch order, i.e. the printer the normal selection would hand it if its filament were loaded. Idle only, so a busy printer's own queue is not disturbed. Nothing is stored; it is recomputed every pass. `item.printer_id` is not set.
- **Notification once.** The state is the saved waiting reason plus an in-memory marker, so passes and restarts do not repeat it.
- **No migration.** Both settings are key/value rows. A missing row reads as the defaults.

**Known limits**
- A **fully busy fleet reserves nothing** until a printer becomes idle. The job keeps its priority; the first printer to become idle is reserved on the next pass, and the priority job wins it.
- An **earlier reservation can hide a later priority job's need.** Each printer is reserved once per pass, so a second priority job for the same printer shows "Busy" until the first one starts.
- **Turning the mode on with an old backlog** gives old jobs priority at once, because the wait is counted from when they were queued.
