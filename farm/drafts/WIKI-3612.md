````markdown
### Printing on a label printer

With a label printer [set up](#label-printer), Bambuddy prints the labels itself. No PDF and no extra software. The print runs on the Bambuddy server, so it works the same from a phone, a tablet or a desktop, and also behind a reverse proxy.

**From the picker**

1. Choose **Roll (label printer tape)** and set the tape and the length. The tape must be the one set in **Settings > Filament > Label printer**.
2. Check the preview.
3. Click **Print on label printer**.

Labels print in black and white, whatever the **Monochrome** option says. The button shows **Printing N labels…** while the printer works, and a toast says **Printed N labels** when it is done. You can close the picker once the print has started. The toast follows the print. If something is wrong, the toast says what, for example that the cover is open.

The button is off, with a hint under it, when:

- the label size is not the roll format, or the tape differs from the printer's tape. Sheet templates cannot be printed on a roll printer
- more than **100 labels** are selected
- the labels need more than **4000 mm** of tape in total (labels × length)

**Per spool.** The printer icon on a spool opens the same picker with that spool selected. Click **Print on label printer** there.

**When you add a spool**

With a label printer set up, the **Add Spool** form has a **Print label after saving** checkbox under its header. Tick it and each new spool gets a label when it is saved. With **Quick Add** and a **Quantity**, one label is printed per created spool. The box is remembered on that device. It is not shown when no printer is set up, and not when you edit a spool.

The label uses the roll format with the tape from the settings and a length of 40 mm. If the printer fails, the spool is still saved, and a toast says why the label did not print.

!!! note "Tape is used"
    Printing needs the same permission as downloading labels, `inventory:read`. Everyone who can see the inventory can print, and every label uses tape.

!!! tip "Print queue"
    Prints wait for each other. If two people print at once, the second print starts when the first has finished.
````

````markdown
### Label printer

Print spool labels straight on a network label printer. **Settings > Filament > Label printer**. [#3612](https://github.com/maziggy/bambuddy/issues/3612)

| Setting | Description |
|---------|-------------|
| **Printer type** | **Off** or **Brother QL (network)**. While it is **Off** the other fields are disabled, and no Print button or checkbox appears anywhere |
| **Address** | The printer's IP address or name, for example `192.168.1.50` or `label-printer.local`. Add `:port` for another port. The default is 9100 |
| **Model** | QL-800, QL-810W or QL-820NWB. The default is QL-820NWB |
| **Loaded tape** | The width of the continuous tape in the printer, for example **50 mm continuous (DK-22223)**. The options are 12, 29, 38, 50, 54 and 62 mm |
| **Test print** | Prints a small test label with the values on the page, saved or not |

The settings save like the others on the page.

**Set up a Brother QL-820NWB**

1. Connect the printer to your network, by cable or Wi-Fi.
2. Give it a **fixed IP address**: a reservation in your router, or a static address in the printer's own network settings. Bambuddy keeps the address, so it must not change.
3. Make sure **raw port 9100** is on. It is on by default. It is the port the printer takes print data on, and it needs no password. If you changed it, enter it in **Address** as `192.168.1.50:9100`.
4. Load the tape, for example DK-22223 (50 mm), and close the cover.
5. In Bambuddy open **Settings > Filament > Label printer**. Choose **Brother QL (network)**, enter the address, choose **QL-820NWB** and **50 mm continuous (DK-22223)**.
6. Click **Test print**.

**What the test answer means**

| Answer | Meaning |
|--------|---------|
| **Test label sent. Printer answered: 50 mm continuous tape** | It worked, and the printer reported the tape it has. Check that it is the tape you chose |
| **Test label sent.** | It worked. This printer sent no status, so Bambuddy could not read the tape. It prints anyway |
| **Printer reports: …** | The printer reported a problem, for example **cover open** or **no tape loaded**. Fix it and try again |
| **The printer has 62 mm tape loaded, the settings say 50 mm** | **Loaded tape** does not match the tape in the printer. Change one of them |
| **Label printer not reachable at …** | Bambuddy cannot connect. See [Troubleshooting](../reference/troubleshooting.md#label-printer-issues) |

The test label shows "Bambuddy test label", the tape, the model and the date. It prints on the tape you chose, and uses a little tape.

!!! info "Who can change it"
    Changing the settings and the test print need the `settings:update` permission. Printing labels needs only `inventory:read`. The address is not shown to users without `settings:read`; they only learn that a printer is set up.

!!! warning "Use a trusted network"
    Port 9100 takes print data from anyone who can reach it. Keep the printer on your home or workshop network, not on the internet.

!!! note "Other printers"
    Brother QL is the first supported family. Others can be added without changes to how you print.
````

## 2. `docs/reference/troubleshooting.md`

Insert **before** `## :material-cog: General Issues`, after the `---` that closes Backup Issues:

````markdown
## :material-label: Label Printer Issues { #label-printer-issues }

For setup, see [Label printer](../features/inventory.md#label-printer).

### "Label printer not reachable"

Bambuddy could not connect to the printer.

1. Check that the printer is on and on the network. Ping its address from the Bambuddy server.
2. Check the **Address** in **Settings > Filament > Label printer**. If the printer got a new address from your router, give it a fixed one.
3. Check that **raw port 9100** is on in the printer's network settings, or enter the port you use as `192.168.1.50:PORT`.
4. In Docker, check that the container can reach the printer's network. Bridge mode usually can. A separate VLAN needs a firewall rule.

Print routes do not show the address in the error, for privacy. The **Test print** button in the settings does.

### "The printer has … tape loaded, the settings say …"

The tape in the printer is not the tape in **Loaded tape**. Change the setting, or load the right tape. Roll labels must use the same tape width as the setting, or the Print button stays off.

### "Label printer reports: cover open" (or "no tape loaded", "end of tape", "cutter jam")

The printer reported a fault. Close the cover, load tape, or clear the cutter, then print again. The printer may also say "wrong tape loaded", "tape cannot be fed", "printer buffer full" or "fan motor error".

### "The label printer did not confirm all labels"

Some labels were sent, but the printer did not say it had printed all of them. Look at the printer and count the labels before you print again, or you may get duplicates. Often the printer ran out of tape, was switched off, or lost the network.

### "The label printer is busy or not taking data"

The printer is printing something else, or it is not reading. Another print from Bambuddy may still be running. Wait a moment and try again. If it stays, switch the printer off and on.

### Printing hangs or fails behind a reverse proxy

Prints do not depend on the length of one request. Bambuddy queues the job and the page asks for its state about once a second. If you still see **The request timed out on the way to Bambuddy**, the proxy cut the connection. Check whether the label printed before you try again. Make sure the proxy passes `GET /api/v1/labels/print-jobs/…` too.

### Labels come out upside down, mirrored or cut off

Check that **Model** and **Loaded tape** match the printer and tape. If the text is still wrong on your printer, open an issue with the model and tape.
````

````markdown
### Print Labels on a Label Printer

Print spool labels on the configured network label printer ([Label printer](../features/inventory.md#label-printer)).

```http
POST /inventory/labels/print
POST /spoolman/labels/print
```

The body is the label request without `format`, `dpi` and `starting_position`.

```json
{
  "template": "roll",
  "roll": { "tape": "50", "length_mm": 40 },
  "fields": ["brand", "material"],
  "spool_ids": [12, 13]
}
```

| Field | Description |
|-------|-------------|
| `template` | Must be `roll` |
| `roll.tape` | Tape width in mm as text: `12`, `29`, `38`, `50`, `54` or `62`. Must equal the tape in the settings |
| `roll.length_mm` | 20 to 200 |
| `fields` | The lines to print, as for the label download. Optional |
| `spool_ids` | 1 to 100 spool ids |

The request is checked, the labels are queued, and the answer comes at once. Printing continues on the server.

**Response:** `202 Accepted`

```json
{ "job_id": "9f1c0b6e2d4a4f0f8a7e6f3b2c1d0e9a", "total": 2 }
```

**Errors:**

- `400` - No label printer is set up, the template is not `roll`, or the tape differs from the printer's
- `404` - A spool does not exist
- `422` - Invalid body, more than 100 labels, or more than 4000 mm of tape in total

**Permission:** `inventory:read` (for API keys, the **Read Status** scope)

!!! note "Printing uses tape"
    Anyone who can download labels can print them. Each request uses tape.

### Get a Label Print Job

```http
GET /labels/print-jobs/{job_id}
```

```json
{ "job_id": "9f1c0b6e2d4a4f0f8a7e6f3b2c1d0e9a", "state": "printing", "printed": 0, "total": 2, "error": null }
```

| `state` | Meaning |
|---------|---------|
| `queued` | Waiting for earlier jobs on the same printer. Jobs for one printer run one at a time |
| `printing` | Being sent to the printer |
| `done` | The printer confirmed all labels. `printed` equals `total` |
| `failed` | `error` says why, for example `Label printer reports: cover open`. It does not name the printer's address |

Poll about once a second until `done` or `failed`.

**Errors:**

- `404` - Unknown or expired job id. Jobs are kept in memory for 15 minutes after they finish, up to 200 jobs, and are lost when Bambuddy restarts

**Permission:** `inventory:read`

### Test the Label Printer

```http
POST /settings/label-printer/test
```

Prints a small test label and waits for the printer. The body is optional. Give any of `type`, `host`, `model` and `tape` to test values you have not saved. Missing ones come from the saved settings.

```json
{ "type": "brother_ql", "host": "192.168.1.50", "model": "QL-820NWB", "tape": "50" }
```

**Response:**

```json
{ "status": { "media_width_mm": 50, "media_type": "continuous", "errors": [], "status_type": "reply", "phase": "waiting" } }
```

`status` is `null` when the printer sent no status.

**Errors:**

- `400` - No label printer is set up
- `409` - The tape in the printer is not the tape in the settings
- `422` - Invalid address, type, model or tape. The address must be a LAN address
- `502` - The printer is not reachable (the error names the address here) or reports a fault
- `503` - The printer is busy
- `504` - The printer did not confirm the label

**Permission:** `settings:update`
````
